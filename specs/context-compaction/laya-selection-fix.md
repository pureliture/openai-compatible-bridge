# Draft PR #19: Laya 후보 선택 수정 및 로컬 재검증

## 결론

Laya가 중간 줄을 놓쳤을 때 기존 코드는 필수 줄이 빠진 규칙 축약본으로 돌아갔다. **이 동작을 수정했다.** 이제 목표와 관련된 줄을 안전하게 하나로 좁힐 수 없는 경우나 모델이 skip/실패/타임아웃을 반환한 경우에는 원문을 유지한다. 후보가 하나인 경우에는 해당 줄만 제한된 선택지로 보내고 원문과 일치하는 줄만 추가한다. 이것은 원문 보존 실패를 막는 개발 수정이지, 실제 Laya 선택 정확도가 높아졌다는 증거가 아니다.

## 수정 전 원인

- M2는 기준선에 없고 길이가 짧은 줄을 목표와 관계없이 최대 16개 뽑아 8개씩 나눠 보냈다. 합성 기술 출력의 필수 줄과 무관한 문장도 경쟁했고, 호출은 사례당 최대 두 번 발생했다.
- `skip`, 불확실한 결정 및 원격 실패에서는 추가 줄을 받지 못해 기준 규칙 축약본을 그대로 저장했다. 실제 Laya의 이전 개발 머신 비교에서 M2 4건 중 필요한 줄 3건이 누락된 사실과 일치하는 위험 경로다. 원격 서버의 선택지 원본을 기록하지 않았으므로 각 누락의 직접 원인이 skip인지 오선택인지 단정하지 않는다.
- 긴 관련 줄이 후보 길이 제한을 넘거나 기준선에 관련 줄이 이미 포함된 경우, 남은 줄만 보고 판단하면 앞뒤 증거가 다를 수 있다.

## 수정 후 조건

- 목표에 나타난 의미 있는 단어와 겹치는 후보가 정확히 한 줄이고, 기준선에 관련 줄이 없으며, 너무 긴 관련 줄도 없을 때만 원격 선택을 요청한다. 후보가 없거나 여럿이면 축약하지 않는다.
- 선택 지시는 현재 목표에 **직접 답하는 줄**을 고르고 그렇지 않으면 skip하도록 명시한다. 결과 텍스트는 생성하지 않고 선택된 원문 줄만 복사한다.
- 모델 실패/타임아웃/skip 및 후보 불명확 상태에서 `run_turn()`은 `verification_failed`를 반환하고 저장 항목을 만들지 않는다. 상위 제공업체에 전달되는 tool 결과도 원문이다.
- 이 단어 겹침은 완전한 의미 판별이 아니다. 동의어나 언어별 표현을 놓치면 원문이 남아 축약 이득이 줄어든다. 서로 다른 필수 정보가 한 줄에 섞이거나 모델이 잘못된 한 줄을 고를 위험도 여전하므로 운영 승인으로 해석하지 않는다.

수정 전 새 회귀 테스트는 3건 실패했으며, 관련 줄이 여러 개인 새 사례와 긴 관련 줄 사례도 각각 수정 전 실패를 확인했다. 수정 후 집중 **50 passed, 경고 1건**, 전체 **759 passed, 경고 1건**(최종 재실행 72.36초). Ruff·lock·diff 검사 모두 exit 0. 경고는 기존 Starlette/httpx TestClient 경고다.

로컬 비교(합성 데이터, 실제 Laya 원격 호출 **0회**): 규칙은 기술 결과 6건의 필수 중간 줄을 **6/6 누락**한다. `skip` 모의 응답일 때 새 경로는 **6/6 원문 유지, 누락 0/6, 모의 호출 6회**다. 정답을 고르는 모의 응답은 **6/6 원문 줄 보존, 누락 0/6, 모의 호출 6회**이며 축약본은 원문보다 짧다. 이 두 0/6은 각각 원문 유지와 모의 정답 선택으로 이유가 다르다. M3은 변경하지 않았고 모의 skip **0/3**, 모의 정답 **3/3**이다. 사례별 길이·로컬 시간은 위 스크립트 JSON에서 확인할 수 있다. 로컬 시간은 원격 지연이 아니다.

**비교 조건 구분:** 직전 실제 Laya 서버 결과는 *수정 전* 같은 기술 M2 4건에서 규칙 누락 4/4, Laya 후 누락 3/4, M3 순위 0/3→0/3 (3회 반복)이었다. 이 수정본에서는 서버 요청 본문·로그 보관 정책 게이트가 미확인이라 원격 호출하지 않았다. 수정 후 실제 Laya 정확도, 추가 원격 지연, 비용, 사용자의 실제 도메인 품질은 미검증이다. 운영 Laya 활성화·PR 머지·배포는 보류한다.
