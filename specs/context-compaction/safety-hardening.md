# PR #19 안전 결함 수정과 남은 승인 조건

## 결론

긴 필수 경로 누락, 승인되지 않은 서버로 원문을 보내는 경로, 모호한 확률 응답 수용을 수정했다. 코드 테스트 성공은 Laya 운영 사용·머지·배포 승인이 아니다. 기본값은 OFF이며 #19는 Draft로 유지한다.

이 문서는 `c60be2b` 이후 수정본의 설정과 검증 기준이다. 기존 `laya-remote-integration.md`의 URL만 사용하는 명령, 모든 실패에서 규칙 축약본으로 돌아간다는 설명, 후보 16줄 설정 설명은 최신 실행 지시로 사용하지 않는다. 설계의 M0/M1은 범위 축소 구현이고, M2/M3는 운영 미채택 후보, M4는 범위 밖이다.

## 수정 내용

| 결함 | 수정 | 직접 확인 |
| --- | --- | --- |
| 240자를 넘는 경로와 개수 초과 증거 누락 | 전체 원문에서 경로·ID·제약을 먼저 찾고 한도 초과 시 원문 유지. 저장 직전에도 필수 줄 포함 여부 확인 | 긴 경로, 경로 14개, ID+경로 합산 초과, 잘못된 선택기 출력의 새 테스트 4건이 수정 전 실패하고 수정 후 통과 |
| 임의의 원격 서버로 제한 원문 전송 | 별도로 승인된 HTTP(S) scheme/IP/port 일치. Tailscale IPv4 범위의 리터럴 주소만 허용. 공개 주소·DNS 이름·그 외 사설/loopback 주소는 금지 | 미승인 주소·리디렉션 테스트 4건이 수정 전 실패. 승인 대상 불일치와 잘못된 URL은 요청 전 거절 |
| 동률·불완전한 확률 응답 수용 | 모든 선택지의 유효한 확률, 합계 1(허용 오차 0.001), 유일한 최고점, answer_confidence 일치 검사 | 새 분포 테스트 중 7건이 수정 전 실패. M2/M3 실제 어댑터 경유 테스트 3건도 수정 전 실패 |

Laya의 HTTP 클라이언트는 환경 프록시를 사용하지 않으며 GET/POST 모두 리디렉션을 따라가지 않는다. Tailscale 주소라는 사실만으로 서버 신원·네트워크 접근 정책·본문 보관 안전이 증명되지는 않는다.

M2 선택이 실패·불확실하면 원문을 유지한다. M3 정렬이 실패·불확실하면 규칙 순서와 전체 목록을 유지한다. 자동 복원하지 않는다. 점수 0.75 기준은 보정된 정확도가 아니며, 근접 점수의 별도 기준은 도메인 평가 없이 새로 정하지 않았다.

## 최신 설정

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `CONTEXT_COMPACTION_ENABLED` | false | 축약 전체 활성화 |
| `CONTEXT_COMPACTION_LAYA_ENABLED` | false | Laya 후보 호출 허용 |
| `CONTEXT_COMPACTION_LAYA_VALIDATED` | false | 품질 검증과 운영 승인을 확인한 운영자 표시 |
| `LAYA_BASE_URL` | 빈 값 | 접속할 실제 서버 origin |
| `LAYA_APPROVED_ORIGIN` | 빈 값 | 별도로 승인한 동일 scheme/IP/port. 코드에 실제 주소를 넣지 않음 |
| `LAYA_REMOTE_TEST_APPROVED` | false | 본문·로그 보관 정책 확인 후 합성 원격 시험을 허용하는 별도 표시. 운영 기능 활성화와 다름 |
| `CONTEXT_COMPACTION_LAYA_TIMEOUT_SECONDS` | 60 | 앱의 단일 Laya 요청 제한 시간 |

세 활성화 스위치와 두 origin 설정이 있어야 앱에서 Laya를 생성한다. 잘못된 origin은 생성 전에 거절한다. 두 origin은 운영자가 확인한 me707 주소로 제한해야 한다. 서버가 바뀌면 승인 대상도 별도로 다시 검토한다. 모델 선택은 계속 `model: multilingual`, 응답 확인은 `routing.model`이다. 브리지에 Laya 모델 패키지를 설치하지 않는다.

## 품질 평가의 경계

실제 원격 호출은 이번 수정 검증에서 **0회**다. 동일한 합성 M2 6건/M3 3건에 로컬 대조군을 실행했다.

- 규칙 기준선: M2 필수 중간 줄 6건 누락, M3 정답 1위 0건.
- 항상 skip인 모의 응답: M2 원문 유지로 누락 0건. M3 개선 없음.
- 정답을 알려 준 모의 응답: M2 원문 줄 추가로 누락 0건, M3 정답 1위 3건.

이는 평가기가 실패·개선을 구분한다는 확인이다. JSON의 `remote_calls`는 선택 함수 호출 시도 수이며 로컬 대조군에서는 실제 네트워크 호출이 아니다. 실제 Laya 품질·비용·캐시·운영 p95 증거로 해석하지 않는다. 이전 원격 품질 수치는 이번 확률 검증 수정 전이며 합쳐 점수화하지 않는다.

## 운영 게이트와 처리 순서

1. 독립 코드 검토와 현재 PR HEAD의 CI를 확인한다.
2. Atlas가 실제 브리지 노드→me707 연결, 적용된 접근 정책, Laya 서비스와 수집기의 본문/로그 보관 정책을 읽기 전용으로 확인한다.
3. 본문 보관 정책과 합성 시험 권한이 확인된 경우에만 위 두 origin과 `LAYA_REMOTE_TEST_APPROVED=true`를 승인된 시험 프로세스에 주입한다. 실제 대화·시크릿·유료 제공업체는 시험 입력에서 제외한다.
4. 동일 고정 사례를 실제 어댑터로 비교한다. 원문 유지와 선택 품질 개선을 구분한다. 별도 사용자 작업 성공률·비용·지연 검증이 필요하다.
5. 운영 게이트를 만족하지 못하면 Laya OFF와 Draft·미머지를 유지하고 차단 원인·해소 담당을 기록한다.

현재 `ATLAS_HANDOFF_ENABLED=true`이며 `main` 소스 머지는 이미지 게시와 자동 운영 반영을 시작할 수 있다. Daedalus에서 머지·자동 머지·workflow dispatch·배포·Secret/ACL 변경은 하지 않는다. 운영 반영은 Atlas의 별도 확인 후 진행한다.

## 한계

필수 증거 감지는 여전히 정규식 기반이다. 모든 자유 문장·언어·경로 형식을 보호한다고 주장하지 않는다. 경로 전체를 보호하는 변경으로 파일 목록의 축약 이득이 줄어든다. 저장은 프로세스 메모리와 TTL이며 재시작 복원·Hermes 자체 축약 후 이력 재생성은 보장하지 않는다. 원격 승인 설정은 운영자 확인의 표시일 뿐 자동 인증·감사 시스템은 아니다.
