# Draft #19 Laya 품질 재검증 (오프라인, 운영 미배포)

## 판정

- **구현/테스트 PASS(로컬 범위)**: 보호 및 실패 복귀 회귀 테스트, 전체 테스트 통과. 운영 품질 통과와 다르다.
- **기존 규칙 대비 품질 FAIL(추가 이득 미입증)**: 아래 새 M2 사례는 규칙만으로 원문을 지키며 Laya 호출이 0회다. M3의 모델 선택은 합성 응답으로만 검증했다.
- **안전/미검증 BLOCKED**: 실제 모델의 잘못된 선택 비율, 서버 요청 본문·로그 보관 정책, 도메인 밖 표현과 운영 지연은 미확인.
- **운영 채택 FAIL**: Draft 유지, 머지·배포·스위치 활성화 금지. 운영 안전 게이트는 Atlas가 별도로 판단한다.

## 원인과 수정

기존 보호기는 `ERROR`, 실패, 중복 청구 같은 제한된 표현에 의존했다. 그 밖의 배송 지연 이유, 점검 시각, 미확인 결제, 실패 상태는 중간 행에서 규칙의 처음/끝 발췌에 들지 않을 수 있었다. Laya도 최대 16개 후보에 구간당 한 줄만 선택하므로 모든 필수 정보를 보존하는 보증이 아니다. 줄이 너무 길면 후보에서 빠진다. 해결/미해결을 한 문장만 보고 단정할 수도 없다.

따라서 업무 사건(배송·결제·점검 등) 또는 이유·상태·시간·대기·해결 여부 등 위험 신호가 한국어/영어 결과에 한 번이라도 나타나면 **전체 원문을 유지**한다. 보호 판단은 모델 호출보다 먼저 적용된다. 길이 제한을 넘는 중요 줄도 발췌하지 않는다. 이는 의미를 완전히 이해하는 분류기가 아니다. 미등록 언어·표현과 구조화 데이터의 의미를 놓칠 수 있으며, 일반 텍스트도 과하게 보호해 축약 기회가 줄어든다. 안전 여부가 불명확한 입력의 자동 축약은 여전히 운영 승인 대상이 아니다.

## 같은 사례 비교 (새 평가)

새 평가는 **로컬 합성 사례**, 현재 수정본 규칙과 후보 경로의 짝 비교다. 실제 Laya 서버를 호출하지 않는다. `*_ms`는 로컬 프로세스 경과 시간일 뿐 원격 지연·p95가 아니다. 결과를 원문으로 유지한 건은 양쪽 모두 필수 정보 보존으로 계산한다. 상세 사례별 수치와 호출 수는 위 평가 명령의 JSON 출력에서 재현한다.

| M2 사례 | 필수 줄 | 규칙 누락 | 후보 누락 | 새 누락 | 후보 원격 호출 |
| --- | --- | ---: | ---: | ---: | ---: |
| 배송 이유 한국어/영어 | 각각 중간 줄 | 0/2 | 0/2 | 0/2 | 0 |
| 점검 시간 한국어/영어 | 각각 중간 줄 | 0/2 | 0/2 | 0/2 | 0 |
| 미확인 결제 한국어/영어 | 각각 중간 줄 | 0/2 | 0/2 | 0/2 | 0 |
| 실패 상태 한국어/영어 | 각각 중간 줄 | 0/2 | 0/2 | 0/2 | 0 |
| 합계 | 8개 | 0/8 | 0/8 | 0/8 | 0 |

M3은 검색어에 반복된 `receipt`가 있어 무관한 항목이 규칙 1위이고, 정답은 택배 수거 실패 항목인 **동일한 오순위 입력**에 서로 다른 스크립트 응답을 주었다. 정답은 사례에 미리 고정했다. 각 시나리오는 3개 항목 전부 유지, visibility=compacted 유지, 자동 unhide 없음, 원격 호출 모의 1회다.

| M3 스크립트 응답 | 규칙 1위 적중 | 후보 1위 적중 | 해석 |
| --- | ---: | ---: | --- |
| 정답 선택 | 0 | 1 | 개선 가능 경로만 입증 |
| 다른 오답 선택 | 0 | 0 | 오선택 가능 |
| skip | 0 | 0 | 무개선 가능 |
| 합계 | 0/3 | 1/3 | **실제 Laya 정확도가 아님** |

M3에서 타임아웃/불확실 응답은 별도 자동 테스트로 규칙 순위 복귀를 확인했다. M2에서도 원격 실패·타임아웃·불확실 응답 때 비위험 결과는 규칙의 **정확한 원문 발췌**로, 위험 결과는 원문 전체로 처리하며 자동 복원은 없다.

## 이전 평가와 비교 금지 조건

Atlas의 초기 M2 0/8 → 4/8, M3 0/3 → 0/3은 **수정 전 규칙과 실제 서버를 이용한 별도 합성 평가**다. 새 평가의 0/8 → 0/8은 보호 규칙을 바꾼 뒤 원문 유지를 포함한 오프라인 결과이며, 실제 Laya 모델 품질 개선이나 기존 표의 재측정으로 해석하면 안 된다. 초기 문서의 더 작은 M2 4건/M3 쉬운 3건도 별도 사례다. 운영 서버 주소를 받거나 실제 사용자 데이터·비밀을 전송하지 않았다.

## 남은 위험 및 Atlas 게이트

- 위험 신호가 없는 줄에 숨은 필수 사실은 여전히 누락될 수 있다. 새로운 도메인·언어의 검증된 데이터와 상태 판정 기준이 필요하다.
- 보호가 보수적일수록 축약률은 낮아진다. 상위 모델 usage·캐시·성공 작업 비용, 실제 원격 호출 횟수와 지연 분포는 측정하지 않았다.
- 실제 Laya가 오순위 사례에서 정답을 고르는지는 평가하지 못했다. 오답도 구조적으로 가능하다.
- Laya 서버의 요청 본문·로그 보관 정책과 운영 네트워크 경계는 **미검증**이며 Atlas의 별도 운영 안전 게이트다. 미보관으로 추정하지 않는다.
- 운영 활성화, 이미지 게시, Kubernetes 변경, Secret/ACL 수정, PR 머지 및 main push는 실행하지 않는다.
