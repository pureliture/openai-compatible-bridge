# 기존 코드 정리 및 통합 검증

## 승인 범위

- #18 오류·필수 증거 보호 보완, #17·#18 통합 검증.
- Laya 구현, PR 머지, 운영 배포와 인프라 변경은 제외.
- 향후 Laya는 별도 노드의 공식 `laya-serve` 연결을 전제로 한다. 서버 버전·입력 한도·실제 모델 평가는 후속 작업이다.

## 미추적 파일 판정

- main의 `specs/context-compaction/design.md`와 `implementation-handoff.md`는 #18 추적 문서의 이전 초안이었다. 전체 diff를 검토했으며 독립적인 신규 요구사항이 없었다. 오래된 상태 설명·인증 세션 전제·로컬 절대 경로를 다시 반영하지 않고 미추적 사본을 제거했다.
- #17 작업 폴더의 `.output.txt`는 과거 테스트 변경 diff 출력 조각이며 코드나 검증 원본이 아니므로 제거했다.
- 보존용 브랜치는 생성하지 않았다. 코드 변경은 별도 개발 작업 트리에서 진행한다.

## 보호 보완 체크포인트

기준: #18 `b3aa217`.

- 한국어 오류/실패/미해결 표시, 들여쓰기·소문자 영어 오류, pytest FAILED, JSON 및 음수 exit_code를 원문 유지 대상으로 처리한다.
- ID 등 보호 증거가 개수 또는 한 줄 길이 한도를 넘으면 축약을 거부한다. 첫 일부 증거만 선택하는 기존 동작을 제거했다.
- 테스트 상태, 제약 및 변경 증거를 나타내는 한국어·영어 표지를 보호 발췌에 포함한다.
- 이는 보수적인 패턴 기반 보호이며 모든 언어·자유 문장의 의미를 이해하는 보장이 아니다. 오류를 인용하거나 이미 해결한 결과도 원문 유지할 수 있다.

검증:

1. `uv run --no-sync pytest -q tests/test_compaction_protection.py --tb=short`: 수정 전 오류 보호 7건 실패 확인.
2. 보호 증거 사례 추가 후 같은 명령: 5 failed, 7 passed 확인.
3. `uv run --no-sync pytest -q --tb=short`: 수정 후 494 passed, 기존 Starlette 경고 1건.
4. `git diff --check`: 통과.

실제 제공업체 호출·비용 절감·Laya 효과를 검증한 결과는 아니다. #17 통합 검증은 다음 체크포인트에서 별도로 기록한다.
