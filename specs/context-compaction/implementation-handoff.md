# 구현 세션용 핸즈오프 프롬프트

2026-09-27 범위 축소: 인증된 세션·분기 식별자는 현재 Hermes 요청에 없다. 구현은 Hermes `session_affinity_header`가 넣는 `x-hermes-conversation` 원문 값만 상관 키로 사용한다. 헤더가 없으면 축약하지 않고, `user`·대화 지문·공유 API 키로 대체하지 않는다. 이 키는 소유자 인증이나 분기 격리가 아니다.

아래 본문은 설계 당시의 구현 지시이다. 2026-09-27 범위 축소 구현은 기능 브랜치에 있으며 배포하지 않았다.

---

이 저장소의 `specs/context-compaction/design.md`를 구현해 줘. 이 문서를 이번 기능의 기준으로 읽고, 최신 브랜치·작업 트리·프로젝트 지침 및 관련 코드를 먼저 확인해. 다른 기능의 기존 스펙을 이 기능의 승인으로 해석하지 마. 구현은 별도 작업 브랜치에서 마일스톤별로 진행하고, 각 단계마다 테스트와 diff를 확인해. 코드 검증이 완료되면 커밋과 PR까지 진행해 줘. 배포·운영 변경은 하지 말고 Atlas에 넘겨.

**M0는 범위 축소로 닫혀 있다.** Hermes 클라이언트 소스는 수정하지 않는다. 상관 키는 `x-hermes-conversation` 헤더의 원문 값만 사용한다. `user` 필드, 메시지 내용의 추측, 공유 API 키만으로 세션을 구분하지 마. 헤더가 없으면 축약 상태를 적용하지 마. 이 키로 인증된 소유자·분기 격리가 생겼다고 주장하지 마.

M0가 해결되면 **Foundry의 OpenAI Chat Completions 비스트리밍 경로**에만 opt-in으로 시작해. 대상은 주 LLM이 이미 읽은 과거 `role=tool` 메시지의 긴 **결과 본문**이다. 터미널 명령어나 쿼리문이 들어 있는 `assistant.tool_calls`, 사용자 메시지, 최신 미소비 결과, 미해결 오류·필수 증거는 함부로 축약하지 마. Hermes 원본은 건드리지 않고 전송용 사본에서만 원문을 검증된 발췌 기반 축약본으로 교체해. 호출/결과 ID 연결을 지켜. 원문을 적절한 소유자·세션/분기 범위에 보관하고 `unhide_context` 시 정확한 원문을 돌려줘. 명령·쿼리를 재실행하지 마. 내부 도구 호출은 Hermes에 노출하지 말고, 외부 도구 호출은 정상 전달해. MCP 서버는 추가하지 마.

**Laya의 역할을 둘 다 구현 후보로 검증해.** (1) 압축할 도구 결과의 구간 중 보존할 원문을 선택하는 추출형 선택기, (2) 새 요청과 관련성이 높은 축약 항목의 `unhide` 후보 선정기. Laya는 자유로운 요약문을 생성하지 않는다. 주 LLM이 압축 대상·시점 및 최종 복원 여부를 정하고, 브리지는 보호 규칙·축약본 생성·상태 적용을 맡는다. 먼저 Laya 없는 규칙 기반 기준선을 만들고 같은 평가 사례로 비교한 뒤 성능이 검증된 경우에만 opt-in으로 사용해. 모델 입력 길이, 한국어/영어 혼합, 오분류, 과신 확률, 추론 지연을 확인해. Laya 불가·저신뢰·원문 발췌 검증 실패 시 원문을 유지하거나 검증된 규칙 기반 경로만 사용해. Laya 결과를 보안·시크릿 삭제 판단으로 사용하지 마.

**캐시와 비용을 실제로 검증해.** 축약본은 전환할 때 한 번 만들어 후속 요청에서 동일 바이트로 유지하고, 매 요청 재생성하거나 임의로 자동 복원하지 마. 축약 직후의 앞부분 변경과 이후의 새 캐시 재사용 가능성을 구별해. 실제 제공업체가 반환하는 캐시 읽기/쓰기 토큰이 있다면 손실 없이 기록하고, 추가 내부 모델 호출도 모두 비용 예약·계상해. 모의 테스트만으로 캐시 적중이나 절감을 주장하지 마. 세션 간 상태 분리, 원문 복원, 오류·필수 증거 보호, 동일 입력/상태의 동일 전송용 과거 메시지, 저장소 장애, 중복·병렬 요청, 강제 `tool_choice`, 내부/외부 도구 혼합을 테스트해. 스트리밍은 내부 호출이 클라이언트에 누출되지 않도록 별도 마일스톤에서 다뤄.
