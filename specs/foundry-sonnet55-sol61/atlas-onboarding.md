# Foundry Sonnet 5.5 / GPT-6.1 Sol 등록·운영 인계

## 목표와 범위

기존 모델 설정을 보존하면서 다음 두 모델을 운영 브릿지에 추가한다.

| 브릿지 별칭 | Foundry 요청 `model` 값 | 프로토콜 |
|---|---|---|
| `foundry:claude-sonnet-5.5` | `ri.language-model-service..language-model.anthropic-claude-5-5-sonnet` | `anthropic_messages` |
| `foundry:gpt-6.1-sol` | `ri.language-model-service..language-model.gpt-6-1-sol` | `openai_responses` |

사용자가 제공한 Foundry 카탈로그 자료에서 두 모델은 Experimental로 표시된다. RID는 제공 자료의 값을 그대로 사용한다. GPT는 제공 자료에서 두 OpenAI 경로를 지원한다고 설명하지만, 이번 실제 검증은 Responses 경로만 대상으로 했다.

등록 항목은 [`../../examples/foundry-sonnet55-sol61.json`](../../examples/foundry-sonnet55-sol61.json)에 있다. **전체 운영 설정이 아니라 추가할 두 항목만 담은 파일**이다. 파일 자체를 `MODEL_REGISTRY_JSON` 값으로 교체하면 기존 환경변수에 있던 별칭들이 사라진다. 반드시 운영의 현재 JSON 객체에 병합한다. 브릿지는 환경변수 값을 기본 내장 목록에 병합할 뿐, 이전 환경변수 값을 보존해 주지 않는다.

## 현재 확인된 사실

2026-09-30 Daedalus 점검 시점의 결과다. 운영 적용 전 Atlas가 다시 확인한다.

- 운영 Secret에는 기존 `foundry:claude-opus-5.5`, `foundry:gpt-6-sol`, `foundry:grok-4.7`가 있다. Git 초안의 커밋 여부로 이들의 운영 등록 여부를 판단해서는 안 된다.
- 이번 신규 별칭 두 개는 운영 Secret에 없다.
- `COST_TRACKING_ENABLED=true`, Foundry 분류는 `nonbillable`이다. 현재 소스 계약에서는 유효한 이 분류가 가격·비용 경로를 우회한다. 신규 가격 항목이 없다는 이유만으로 요청이 차단되지는 않는다. 이 설정이 실제 청구 계약의 증거는 아니며, 분류 변경이나 0원 가격 추가를 이번 작업에서 하지 않는다.
- Deployment는 원하는 Pod 1개 중 Ready/Available 1개였다.
- 기존 소비자용 HTTPS 주소의 `GET /v1/models`는 기본 요청과 환경 프록시를 사용하지 않은 요청 모두 HTTP 502였다. Pod 준비 상태만으로 소비자 경로가 정상이라고 판단할 수 없다. 배포 전후에 Atlas가 해당 경로를 확인하고 복구해야 한다.
- Secret 수정, 재시작, 이미지 게시, 배포는 Daedalus가 수행하지 않았다.

## 검증 증거

- 첫 등록 테스트는 추가 파일이 없는 상태에서 실패했고, 파일을 추가한 뒤 통과했다.
- 모의 HTTP 서버를 사용하며 운영 등록을 증명하지 않는다.

### 실제 Foundry 호출

기존 브릿지 컨테이너의 `/app/.venv/bin/python`에서 **배포된 `FoundryChatClient` 변환·응답 검사 코드**를 사용했다. 컨테이너의 기존 인증·접속 설정을 그대로 사용했으며 인증값, URL, 응답 원문은 기록하지 않았다. 짧은 합성 요청만 보냈고 서버 파일이나 설정은 바꾸지 않았다. 이 요청은 브릿지의 HTTP 진입점 및 비용 처리 경로를 거치지 않으므로, 운영 별칭 등록이나 소비자 연결의 증거와 구분한다.

최종 검증 결과:

| 모델 | 일반 응답 | 스트리밍 | `tool_choice=auto` 도구 호출 |
|---|---|---|---|
| Sonnet 5.5 / Anthropic | 성공, `OK` 일치 | 비어 있지 않은 텍스트 수신, `OK` 정확 일치는 아님 | `contract_echo(value=ok)` 정상 변환 |
| GPT-6.1 Sol / Responses | 성공, `OK` 일치 | 성공, `OK` 일치 | `contract_echo(value=ok)` 정상 변환 |

일반 요청의 변환 후 사용량: Sonnet 입력 18 / 출력 4 / 합계 22 토큰, GPT 입력 11 / 출력 5 / 합계 16 토큰. 최종 각 요청의 관측 시간은 0.94~1.80초였다. 이는 작은 요청의 단일 측정이며 성능 보장이 아니다.

제한과 실패도 보존한다:

- 앞선 Sonnet 특정 도구 강제 선택 요청은 HTTP 400 `invalid_request_error`였다. `auto` 재검증은 성공했다. 강제 선택 실패의 세부 원인은 아직 확인하지 않았으며 지원된다고 주장하지 않는다.
- 첫 검증 도구는 가상환경 밖 Python을 사용해 `httpx` import가 실패했다. 가상환경 경로로 수정했다.
- 첫 스트리밍 검증은 실제 메서드 이름과 다른 이름을 호출해 실패했다. 배포 소스의 `stream_chat`과 `delta_text`를 사용하도록 고친 뒤 실제 스트림을 검증했다. 이를 모델 실패로 취급하지 않는다.
- GPT Chat Completions 경로, 도구 호출 스트리밍, 추론 수준별 동작, 이미지 입력, 큰 컨텍스트와 품질은 이번 실제 검증 범위 밖이다.

## Atlas 실행 순서

1. 현재 Secret의 기존 `MODEL_REGISTRY_JSON`과 배포 설정을 승인된 비밀 저장 위치에 백업한다. 인증값이나 전체 Secret을 Git·채팅·인계 문서에 쓰지 않는다.
2. 소비자용 브릿지 `GET /v1/models`의 HTTP 502 원인을 확인한다. Ready Pod와 별개로 서비스·프록시·소비자 연결을 검사한다. Daedalus의 이번 인계에서 해당 운영 경로를 복구하지 않았다.
3. 현재 레지스트리와 추가 항목의 별칭 충돌을 확인한다. 이미 같은 값으로 등록됐으면 중복 수정하지 않는다. 다른 값이면 임의 덮어쓰기하지 않고 원인을 먼저 판단한다.
4. 기존 JSON 객체에 두 항목을 추가하고, 이전 별칭·설정이 모두 동일하게 남았는지 비교한다. 다른 provider와 비용 설정, 컨텍스트 축약 설정을 변경하지 않는다. Foundry 분류도 다시 확인한다. 만약 현재 분류가 `metered`라면 승인된 실제 가격을 두 별칭의 chat 입력/출력 항목에 먼저 추가해야 하며, 보호 기능을 끄거나 가격을 추측하지 않는다.
5. 운영 Secret에 병합된 값을 반영한다. 레지스트리는 import 시 읽으므로 승인된 재시작 절차가 필요하다. 이번 변경은 등록 파일·테스트·문서만 추가하며 기존 어댑터를 그대로 사용하므로 **이미지 재빌드는 필수가 아니다**.
6. Secret의 대상 키를 다시 읽어 기존 항목 보존 및 신규 값 일치를 확인한다. Pod 준비 상태를 확인한 뒤, 실제 소비자 네트워크에서 `/v1/models`에 두 별칭이 나타나는지 확인한다.
7. 소비자용 `/v1/chat/completions`에서 각 **별칭**으로 일반 응답·스트리밍·`tool_choice=auto` 도구 호출을 실행한다. 내용, usage와 정상 종료를 검사하고 기존 모델에도 작은 회귀 요청을 한다. 이 단계까지 성공해야 운영 등록·배포 완료라고 보고한다.
8. 모델 목록 동기화가 운영 중이면 신규 별칭이 소비자 모델 선택 목록에도 나타나는지 확인한다. 임의로 다른 Hermes 프로필 설정을 변경하지 않는다.

## 롤백

이번 적용으로 문제가 생기면 Atlas가 승인된 절차로 백업한 레지스트리 값을 복원하고 재시작한다. 이미지를 바꾸지 않은 경우 이미지 롤백은 필요하지 않다. 신규 별칭만 제거해도 되는지와 동시 설정 변경 유무를 먼저 확인한다. 복원 후 기존 목록과 기존 모델 호출, 소비자 경로를 다시 검사한다.

## 완료 기준

- 기존 운영 모델의 설정과 호출이 보존됨.
- 신규 두 별칭이 소비자용 `/v1/models`에 표시됨.
- 각 별칭의 일반 응답·스트리밍·자동 도구 호출이 실제 소비자 경로에서 성공함.
- 기존 비용 분류와 보호 설정이 보존됨.
- 적용 뒤 상태를 다시 읽은 증거와 필요한 롤백 경로가 있음.

현재 이 문서는 **배포 인계**이며 운영 적용 완료 보고서가 아니다.
